# Контрольное задание №2 — JWT, bcrypt и роли

Клиент-серверное приложение магазина на основе практик №10–11.

- Обычный пользователь (`user`) после входа просматривает товары.
- Сотрудник (`employee`) просматривает, создаёт, изменяет и удаляет товары.
- Пароль хранится как bcrypt-хеш.
- После входа сервер выдаёт JWT access-токен. Клиент отправляет его в `Authorization: Bearer <token>`.
- Текущий пользователь: защищённый маршрут `GET /api/auth/me`.

## Запуск

Нужны Node.js 18+ и два терминала.

### Сервер

```bash
cd backend
npm install
npm run dev
```

- API: http://localhost:3000
- Swagger: http://localhost:3000/api-docs

### Клиент

```bash
cd frontend
npm install
npm run dev
```

- Интерфейс: http://localhost:3001

## Демо-аккаунты

Пользователи живут в памяти процесса и создаются при старте сервера.

| Email | Пароль | Роль |
|---|---|---|
| user@mail.ru | user12345 | обычный пользователь |
| employee@mail.ru | employee12345 | сотрудник |

Новый аккаунт можно зарегистрировать в интерфейсе и выбрать роль. Пароль в ответе сервера не возвращается, сохраняется только хеш.

## Что показать на сдаче

1. Регистрация и вход.
2. JWT access-токен на экране после входа. Его можно вставить в Swagger через Authorize.
3. `GET /api/auth/me` — кнопка «Обновить /me» или тот же запрос в Swagger.
4. Вход под `user@mail.ru`: список товаров есть, кнопок управления нет.
5. Кнопка «Попробовать создать товар» у обычного пользователя — сервер отвечает `403`.
6. Вход под `employee@mail.ru`: создание, изменение цены и удаление проходят успешно.

Без токена `GET /api/products` тоже отвечает `401`.

## Как устроена проверка доступа

1. `POST /api/auth/register` хеширует пароль через `bcrypt.hash` и сохраняет `passwordHash`.
2. `POST /api/auth/login` сравнивает пароль через `bcrypt.compare` и подписывает JWT. В payload есть `sub`, `email` и `role`.
3. `authMiddleware` читает заголовок `Authorization: Bearer <token>` и проверяет подпись и срок действия. Иначе `401`.
4. `requireRole("employee")` сравнивает роль из токена. Если роль другая — `403`, обработчик маршрута не вызывается.
5. Клиент хранит токен в `localStorage` и подставляет его через axios interceptor (`frontend/src/api/apiClient.js`).

Создание, изменение и удаление товаров закрыты ролью сотрудника: `POST`, `PUT`, `PATCH`, `DELETE /api/products`. Просмотр (`GET`) доступен любому вошедшему пользователю.

## Структура

- `backend/app.js` — сервер, CORS, Swagger
- `backend/routes/auth.js` — регистрация, вход, refresh, `/me`
- `backend/routes/products.js` — товары и проверка роли
- `backend/middleware/authJwt.js` — проверка JWT и роли
- `backend/store/usersStore.js` — пользователи в памяти, демо-аккаунты
- `frontend/src/App.jsx` — регистрация, вход, список и управление товарами
