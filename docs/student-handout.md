# Как показывать контрольное задание №2

Подробный запуск — в `README.md`.

## Роли

| Действие | Обычный пользователь | Сотрудник |
|---|---|---|
| `GET /api/auth/me` | да | да |
| `GET /api/products` | да | да |
| `POST`, `PUT`, `PATCH`, `DELETE /api/products` | нет, ответ 403 | да |

Демо-вход: `user@mail.ru` / `user12345` и `employee@mail.ru` / `employee12345`.

## Что сказать про механизм

1. При регистрации пароль проходит через `bcrypt.hash`. В памяти лежит хеш, не пароль.
2. При входе `bcrypt.compare` проверяет пароль. Сервер подписывает JWT секретом и кладёт в него id, email и роль.
3. Защищённые маршруты стоят за `authMiddleware`: он проверяет заголовок `Authorization: Bearer` и срок токена.
4. Операции изменения товара дополнительно проходят через `requireRole("employee")`. Чужая роль получает 403 до выполнения операции.
5. Клиент после входа сохраняет access-токен и добавляет его ко всем запросам автоматически.
